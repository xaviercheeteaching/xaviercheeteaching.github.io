Chapter 1: Python Fundamentals for Precision Health#

1. Introduction#

Welcome to the study of function return values, a fundamental concept for creating powerful and modular code in precision health applications. In this section, we will explore how to use the return statement to send data out of a function. The primary goal is to learn how a function can perform a calculation, such as determining a drug dosage or assessing patient vitals, and provide the result back to the main program for further use. This journey will cover returning single values, multiple values, and using the special value None to handle errors or signal specific conditions.

2. Key Concepts and Definitions#

Understanding the following terms is essential for building functions that produce results. They provide the vocabulary for describing how data flows out of your reusable code blocks.

  • return Statement: A keyword in Python that immediately exits a function and optionally passes a value back to the caller. In a medical context, this is like a lab test that “returns” a result (e.g., a blood glucose level) to the clinician who ordered it.

  • Return Value: The specific data or object that a function sends back. This could be a single number (like a calculated BMI), a string (a risk assessment category), or a more complex data structure.

  • Tuple: An ordered, immutable collection of items in Python. Functions use tuples to return multiple values at once, packed into a single object. For example, a function could return a patient’s systolic and diastolic pressures as (120, 80).

  • None: A special singleton object in Python representing the absence of a value. In clinical programming, returning None is a standard and effective way to signal that a calculation could not be completed due to invalid input, such as a negative patient weight.

  • Conditional Logic: The use of statements like if, elif, and else to control the flow of a program. In functions, conditional logic is often used with return to exit early if certain conditions are met, preventing errors and improving efficiency.

3. Main Content#

This section covers the mechanics of getting data out of your functions, a critical step in making them useful components of a larger program.

3.1 Return a Single Value#

A function can process data and send back one piece of information. This is the most common use of the return statement. The returned value can be stored in a variable for later use.

def calculate_drug_dosage(patient_weight_kg: float, dose_mg_per_kg: float) -> float:
    """Calculates total dosage based on patient weight.

    Args:
        patient_weight_kg (float): The patient's weight in kilograms.
        dose_mg_per_kg (float): The required dose in mg per kg.

    Returns:
        float: The total calculated dosage in mg.
    """
    total_dosage = patient_weight_kg * dose_mg_per_kg
    return total_dosage

dosage_for_patient = calculate_drug_dosage(70, 1.5)
print(f"Calculated Dosage: {dosage_for_patient} mg")
# Output:
# Calculated Dosage: 105.0 mg

While returning a single value is useful, clinical situations often require handling multiple data points at once. Let’s see how functions can manage this.

3.2 Return Multiple Values#

To return multiple values, you simply list them after the return keyword, separated by commas. Python automatically packs these values into a single tuple object. This tuple can then be “unpacked” into multiple variables, which is highly efficient for returning related pieces of information.

def get_sample_vitals() -> tuple[float, int]:
    """Returns a sample of a patient's core vital signs.

    Returns:
        tuple[float, int]: A tuple containing temperature in Celsius and pulse in bpm.
    """
    temperature_c = 37.0
    pulse_bpm = 72
    return temperature_c, pulse_bpm

# The returned values are packed into a single tuple
vitals_tuple = get_sample_vitals()
print(f"Returned tuple: {vitals_tuple}")
# Output:
# Returned tuple: (37.0, 72)

# The tuple can be "unpacked" into separate variables
temp, pulse = get_sample_vitals()
print(f"Unpacked - Temperature: {temp} °C, Pulse: {pulse} bpm")
# Output:
# Unpacked - Temperature: 37.0 °C, Pulse: 72 bpm

Medical Background: Think of returning a tuple like reading from a multi-parameter patient monitor. The monitor gives you a single “package” of related data (e.g., temperature, pulse, SpO2) at a specific moment. In Python, a tuple serves the same purpose, bundling related values like (37.0, 72) into a single, immutable package for easy transport and use.

Pro Tip: Unpacking a tuple into separate variables, like with temp, pulse = get_sample_vitals(), is considered more readable and “Pythonic” than accessing elements by index (e.g., vitals_tuple[0]). It makes your code’s intent clearer at a glance.

Now that we can return data, it’s crucial to learn how to control when we return it, especially when dealing with invalid or unsafe inputs.

3.3 Early Return with Conditional Logic#

You can place a return statement inside a conditional block (if statement) to exit a function early. This is a powerful pattern for input validation, as it stops the function from executing further if the inputs are invalid. Returning None is a common convention to signal a failure.

def calculate_bmi(weight_kg: float, height_m: float) -> float | None:
    """Calculates Body Mass Index (BMI), returning None if inputs are invalid.

    Args:
        weight_kg (float): Patient's weight in kilograms.
        height_m (float): Patient's height in meters.

    Returns:
        float | None: The calculated BMI, or None if inputs are non-positive.
    """
    if height_m <= 0 or weight_kg <= 0:
        return None  # Exit early if data is invalid
    
    bmi = weight_kg / (height_m ** 2)
    return bmi

# Failure case: Invalid height
patient_bmi_invalid = calculate_bmi(70, 0)
if patient_bmi_invalid is None:
    print("Error: Height and weight must be positive numbers.")
else:
    print(f"Patient BMI: {patient_bmi_invalid:.2f}")
# Output:
# Error: Height and weight must be positive numbers.

# Success case: Valid inputs
patient_bmi_valid = calculate_bmi(70, 1.75)
if patient_bmi_valid is None:
    print("Error: Height and weight must be positive numbers.")
else:
    print(f"Patient BMI: {patient_bmi_valid:.2f}")
# Output:
# Patient BMI: 22.86

Important: Using an early return to handle invalid inputs is a fundamental safety pattern in medical software, often called a “guard clause.” It stops a calculation cold if the input data is nonsensical (like a negative height). This prevents a “garbage in, garbage out” scenario, ensuring that an erroneous calculation never reaches the clinician.

Debug Note: A common error is forgetting to check if a function returned None. If you try to perform math on None (e.g., print(f"{patient_bmi_invalid:.2f}") without the if check), your program will crash with a TypeError. Always handle the possibility of a None return value.

3.4 Implicit None Return#

A function that completes its execution without encountering an explicit return statement will automatically return None. This is common for functions designed only to perform an action (a “side effect”), such as printing to the console, and do not need to produce a result.

def log_abnormal_vital(patient_id: str, message: str) -> None:
    """Logs a warning message to the console. Does not return a value.

    Args:
        patient_id (str): The patient's unique identifier.
        message (str): The warning message to log.
    """
    print(f"[ALERT] Patient {patient_id}: {message}")

# The function prints a message but doesn't explicitly return a value
result = log_abnormal_vital("PT001234", "Heart rate is 110 bpm")
print(f"Return value of log_abnormal_vital: {result}")
# Output:
# [ALERT] Patient PT001234: Heart rate is 110 bpm
# Return value of log_abnormal_vital: None

Exercise 1: Calculate Mean Arterial Pressure (MAP) Intermediate#

Objective: Write a function that calculates Mean Arterial Pressure and handles invalid input using an early return. Time: 7 minutes Medical Context: As part of building a new vital signs monitoring module for an EHR, you need to create a function to calculate Mean Arterial Pressure (MAP). This value is crucial for assessing organ perfusion.

Medical Background: Mean Arterial Pressure (MAP) represents the average pressure in a patient’s arteries during one cardiac cycle. It’s considered a better indicator of organ perfusion than systolic blood pressure alone. The formula is a weighted average, and it’s physiologically impossible for diastolic pressure to be higher than systolic pressure, making this an essential validation check.

Task: Write a function named calculate_map that takes two parameters, systolic and diastolic pressure.

  • The function must use the formula: MAP = Diastolic + (1/3 * (Systolic - Diastolic)).

  • If systolic is not greater than diastolic, the function should return None immediately.

  • Example Call: calculate_map(120, 80) should return approximately 93.33.

  • Example Invalid Call: calculate_map(80, 90) should return None.

Solution

def calculate_map(systolic: float, diastolic: float) -> float | None:
    """Calculates Mean Arterial Pressure (MAP).

    Args:
        systolic (float): Systolic blood pressure.
        diastolic (float): Diastolic blood pressure.

    Returns:
        float | None: The calculated MAP, or None if inputs are invalid.
    """
    if not systolic > diastolic:
        return None  # Invalid physiological state
    
    map_value = diastolic + (1/3 * (systolic - diastolic))
    return map_value

# Valid call
map_result = calculate_map(120, 80)
if map_result is not None:
    print(f"The patient's MAP is: {map_result:.2f} mmHg")

# Invalid call
map_result_invalid = calculate_map(80, 90)
if map_result_invalid is None:
    print("Calculation failed: Systolic pressure must be greater than diastolic pressure.")

Explanation: The function first implements a “guard clause” to check if systolic pressure is greater than diastolic. If not, it immediately returns None. Otherwise, it proceeds to calculate and return the MAP, which the calling code then formats to two decimal places. Key Learning: Using an early return with None is an effective way to handle physiologically impossible or invalid data before performing calculations.

Reflection Moment: Our function checks if systolic > diastolic. What other input validations would be critical for a production-ready version of this function? Consider physiological limits (e.g., negative pressures) and data types.

Exercise 2: Pediatric Dosage Calculator Basic#

Objective: Create a function that returns a single calculated value. Time: 3 minutes Medical Context: Pediatric medication dosages are often calculated based on weight to ensure safety and efficacy. A simple linear calculation is common for many over-the-counter drugs.

Task: Write a function calculate_pediatric_acetaminophen_mg that takes a child’s weight_kg. The dosage is 15 mg per kg. The function should return the total dosage in mg.

def calculate_pediatric_acetaminophen_mg(weight_kg: float) -> float:
    """Calculates a pediatric acetaminophen dosage based on weight.

    Args:
        weight_kg (float): The child's weight in kilograms.

    Returns:
        float: The total recommended dosage in mg.
    """
    dose_per_kg = 15.0  # mg/kg
    total_dose = weight_kg * dose_per_kg
    return total_dose

child_weight = 10.0  # kg
dosage = calculate_pediatric_acetaminophen_mg(child_weight)
print(f"For a {child_weight} kg child, the recommended dose is {dosage} mg.")

Explanation: The function performs a simple multiplication and uses return to send the single result back to the caller. This encapsulates the calculation, making it reusable and less prone to manual error. Key Learning: Functions are ideal for encapsulating a single, reusable calculation rule.

Exercise 3: Assess Kidney Function Advanced#

Objective: Write a function that returns multiple values (a status string and a numerical value) based on conditional logic. Time: 7 minutes Medical Context: Glomerular Filtration Rate (GFR) is a key indicator of kidney function. A GFR below 60 ml/min/1.73m² suggests chronic kidney disease (CKD), while a value below 15 indicates kidney failure.

Task: Write a function assess_gfr that takes a patient’s gfr_value.

  • If gfr_value is less than 15, return the tuple ("Kidney Failure", gfr_value).

  • If gfr_value is between 15 and 60 (inclusive), return ("Potential CKD", gfr_value).

  • If gfr_value is greater than 60, return ("Normal", gfr_value).

def assess_gfr(gfr_value: float) -> tuple[str, float]:
    """Assesses kidney function based on GFR and returns a status and the value.

    Args:
        gfr_value (float): The patient's GFR value.

    Returns:
        tuple[str, float]: A tuple containing the assessment string and the GFR value.
    """
    if gfr_value < 15:
        return "Kidney Failure", gfr_value
    elif 15 <= gfr_value <= 60:
        return "Potential CKD", gfr_value
    else: # gfr_value > 60
        return "Normal", gfr_value

# Example calls
status1, value1 = assess_gfr(90)
print(f"Status: {status1}, GFR: {value1}")

status2, value2 = assess_gfr(45)
print(f"Status: {status2}, GFR: {value2}")

status3, value3 = assess_gfr(10)
print(f"Status: {status3}, GFR: {value3}")

Explanation: The function uses if/elif/else logic to determine the correct status string. In each branch, it returns both the string and the original gfr_value as a tuple, which is then unpacked into two variables by the calling code. Key Learning: Returning multiple values allows a function to provide both a categorical assessment and the specific data point it was based on.

5. Practical Applications#

  • Clinical Risk Scoring: A function can take multiple patient parameters (e.g., age, cholesterol, blood pressure) and return a calculated risk score, such as the Framingham Risk Score for cardiovascular disease. The calling program can then use this score to trigger alerts or recommend interventions.

  • Genomic Data Analysis: In bioinformatics, a function might process a raw DNA sequence file. It could return multiple values, such as a list of identified gene mutations and a dictionary mapping those mutations to known clinical significance, packed together in a tuple for easy unpacking and analysis.

  • Data Validation and Cleaning: When processing electronic health records (EHR), a function can be written to validate patient data. If the data is valid, it might return a cleaned, standardized dictionary of information. If it finds errors (e.g., a temperature of “98.6 F” instead of a number), it could return None to signal that the record needs manual review.

6. Summary and Key Takeaways#

In this section, we’ve explored the essential role of the return statement in making functions useful and modular. We learned that functions are not just for performing actions, but for producing results that can be used throughout a program. By mastering how to return single values, multiple values as tuples, and None for error handling, you can build more robust and reliable applications for precision health.

  • The return statement is used to send a value from a function back to its caller.

  • A function can return any single Python object, such as an integer, string, or list.

  • To return multiple values, list them separated by commas; Python will automatically create a tuple.

  • Returning None is a conventional and effective way to signal an error, invalid input, or the absence of a result.

  • Functions that do not have an explicit return statement implicitly return None.
