Chapter 1: Python Fundamentals for Precision Health#

1. Introduction#

Welcome to the study of default parameters, a powerful Python feature for creating flexible and clean code. In this section, you will learn how to make function arguments optional by assigning them default values. This technique is essential in medical programming, as it simplifies function calls for common scenarios, such as using a standard drug concentration or a default patient status. By establishing sensible defaults, we can write functions that are both easier to use and less prone to data entry errors. By the end of this lesson, you will be able to define more robust and adaptable functions for a variety of clinical applications.

2. Key Concepts and Definitions#

Understanding these terms is crucial for effectively using default parameters in your functions.

  • Default Parameter: A parameter in a function signature that is assigned a value using the = operator. If a function is called without providing an argument for this parameter, the default value is used automatically. For example, in a function log_vitals(hr, bp, temp_unit='C'), temp_unit is a default parameter.

  • Required Parameter: A parameter that does not have a default value. An argument must be explicitly provided for every required parameter when the function is called, otherwise Python will raise a TypeError. In a dosing function, patient_weight would be a required parameter.

  • Function Signature: The first line of a function definition, which includes the def keyword, the function name, and its parameters in parentheses. The order of required and default parameters in the signature is critical.

  • Mutable Default Argument: A default parameter that uses a mutable (changeable) data type, such as a list or dictionary. This is a common but dangerous pitfall, as the default object is shared across all calls to the function, leading to unintended side effects. It’s like having every patient’s new allergy added to a single, shared master list instead of their own individual record.

  • SyntaxError: An error raised by the Python interpreter when it encounters code that violates the language’s grammatical rules. A common cause is placing a required parameter after a default parameter in a function’s signature.

3. Main Content#

This section covers the syntax, rules, and critical best practices for using default parameters in Python, with a focus on medical applications.

3.1 Defining Functions with Default Parameters#

Default parameters make arguments optional by assigning a standard value if one isn’t provided. This is incredibly useful for establishing sensible defaults in clinical calculations.

In Practice: Default parameters simplify function calls for common medical scenarios. For instance, a prescription function can default to a standard 50 mg/mL drug concentration, reducing the risk of data entry errors for routine cases while still allowing for overrides in special situations.

def calculate_med_dose(weight_kg: float, concentration_mg_ml: int = 50) -> None:
    """Calculates dose in mL based on weight and drug concentration.

    Args:
        weight_kg (float): Patient's weight in kilograms.
        concentration_mg_ml (int): Drug concentration in mg/mL. Defaults to 50.
    """
    # NOTE: Hypothetical 10mg/kg regimen for educational purposes only.
    dose_ml = (weight_kg * 10) / concentration_mg_ml
    print(f"Administer {dose_ml:.2f} mL for a {weight_kg} kg patient.")

# Call using the default concentration (50 mg/mL)
calculate_med_dose(70)

# Override the default with a different concentration
calculate_med_dose(70, concentration_mg_ml=100)

3.2 The Parameter Order Rule#

Important: Required Parameters Must Come First

A strict rule in Python is that all required (non-default) parameters must be listed before any default parameters in a function definition. This ordering is essential for the Python interpreter to correctly match arguments to parameters. Violating this rule will cause a SyntaxError.

# CORRECT: Required parameter (weight_kg) is first.
def calculate_med_dose(weight_kg: float, concentration_mg_ml: int = 50) -> None:
    pass

# INCORRECT: This will raise a SyntaxError.
# def calculate_med_dose(concentration_mg_ml: int = 50, weight_kg: float) -> None:
#     pass

3.3 The Pitfall of Mutable Default Arguments#

Important: Avoid Mutable Objects (like lists or dictionaries) as Default Arguments

You must avoid using mutable objects like lists or dictionaries as default arguments. The default object is created only once when the function is defined, not each time it’s called. This means every function call that relies on the default will modify the same object, leading to unexpected and incorrect behavior.

The correct and safe pattern is to set the default value to None (which is immutable) and then, inside the function, check if the argument is None. If it is, you create a new, empty object (e.g., [] or {}). This ensures that each function call operates on a fresh, independent object.

from typing import Optional, List

# INCORRECT: Using a mutable list as a default
def log_medication(medication: str, med_list: List[str] = []) -> None:
    med_list.append(medication)
    print(f"Medications logged: {med_list}")

log_medication("Lisinopril")
log_medication("Metformin") # This incorrectly modifies the original list

Exercise 2: Check Patient Vitals for Tachycardia Intermediate#

Objective: Use a default parameter and conditional logic for a clinical check. Time: 5 minutes Medical Context: This function helps automate initial vitals screening by checking for tachycardia, an abnormally high heart rate.

Medical Background: A resting heart rate over 100 beats per minute (bpm) is the clinical threshold for tachycardia in adults (American Heart Association, 2022).

Task: Create a check_vitals function with the following requirements:

  • It must accept a required resting_heart_rate (HR) argument.

  • It must accept an optional patient_status argument that defaults to 'stable'.

  • If patient_status is not 'stable', print: f'Vitals logged for {patient_status} patient'.

  • If resting_heart_rate (HR) > 100 and patient_status is 'stable', print: 'Tachycardia detected in stable patient'.

  • Otherwise, print: 'Vitals normal for stable patient'.

Solution

# Per AHA, resting heart rate > 100 bpm is tachycardia in adults.
TACHYCARDIA_THRESHOLD_BPM = 100

def check_vitals(resting_heart_rate: int, patient_status: str = 'stable') -> None:
    """Checks patient vitals and flags potential tachycardia.

    Args:
        resting_heart_rate (int): The patient's resting heart rate (HR) in beats per minute.
        patient_status (str): The patient's current status. Defaults to 'stable'.
    """
    if patient_status != 'stable':
        print(f'Vitals logged for {patient_status} patient')
    elif resting_heart_rate > TACHYCARDIA_THRESHOLD_BPM:
        print('Tachycardia detected in stable patient')
    else:
        print('Vitals normal for stable patient')

# Test cases
check_vitals(110)
check_vitals(95)
check_vitals(110, 'unstable')

# Output:
Tachycardia detected in stable patient
Vitals normal for stable patient
Vitals logged for unstable patient

Explanation: The function first checks for the non-default case ('unstable') to prioritize it. If the patient is stable, it then evaluates the heart rate against the TACHYCARDIA_THRESHOLD_BPM constant. Key Learning: Combining default parameters with conditional logic allows for creating flexible functions that can adapt to different clinical scenarios.

Reflection Moment: In the check_vitals solution, we check for the patient_status != 'stable' condition first. Why is this an effective approach? Consider how it simplifies the subsequent logic for the more common ‘stable’ patient case.

Exercise 3: Track Patient Medications Advanced#

Objective: Correctly handle a mutable default argument when tracking patient data. Time: 5 minutes Medical Context: Accurately tracking a patient’s medications is critical for safety. Each patient must have their own distinct list, which should never be accidentally merged with another’s.

Task: Create a function add_medication that takes a patient_id and a new_medication. It should also take an optional medication_list.

  • The function must correctly handle cases where no medication_list is provided, ensuring each patient’s list is independent.

  • It should add the new_medication to the list and print the result: f"Patient {patient_id} medications: {updated_list}".

from typing import Optional, List

def add_medication(patient_id: str, new_medication: str, medication_list: Optional[List[str]] = None) -> List[str]:
    """Adds a medication to a patient's list, creating a new list if one isn't provided."""
    if medication_list is None:
        medication_list = []
    
    medication_list.append(new_medication)
    print(f"Patient {patient_id} medications: {medication_list}")
    return medication_list

# Patient 1 starts a new list and then adds to it
print("--- Patient PT111 ---")
p1_meds = add_medication("PT111", "Lisinopril")
p1_meds = add_medication("PT111", "Aspirin", medication_list=p1_meds)

# Patient 2 starts their own, separate new list
print("\n--- Patient PT222 ---")
p2_meds = add_medication("PT222", "Metformin")

# Output:
--- Patient PT111 ---
Patient PT111 medications: ['Lisinopril']
Patient PT111 medications: ['Lisinopril', 'Aspirin']

--- Patient PT222 ---
Patient PT222 medications: ['Metformin']

Explanation: By defaulting medication_list to None and creating a new list [] inside the function, we ensure that each patient’s medication list is managed independently. The call for Patient PT222 creates a new list, demonstrating that it was not affected by the calls for Patient PT111. Key Learning: Always default mutable parameters to None and initialize them inside the function to prevent shared state and logical errors.

5. Practical Applications#

  • Electronic Health Record (EHR) Systems: When logging a patient encounter, a function like log_visit(patient_id, diagnosis_code, visit_type='Routine') can use a default parameter for visit_type. This speeds up data entry for the most common encounters while allowing for specific overrides like 'Specialist Consultation' or 'Emergency'.

  • Clinical Decision Support: A function to assess sepsis risk, check_sepsis_risk(vitals, lactate, consciousness_level='Alert'), could default the consciousness level to ‘Alert’. This allows the function to be called with just vitals and lab values for most patients, but enables an override for patients with altered mental status, a key sepsis indicator.

  • Genomic Sequencing Pipelines: In bioinformatics, a function that aligns DNA sequences might have default parameters for alignment sensitivity. For example, align_sequence(sequence, reference_genome, sensitivity='high') could default to a high-sensitivity setting for clinical-grade analysis but allow bioinformaticians to set it to 'fast' for preliminary quality checks, saving significant computation time.

6. Summary and Key Takeaways#

In this section, we’ve explored how to use default parameters to create more flexible and readable functions. By setting default values, we can make certain arguments optional, which simplifies function calls for common use cases and reduces the chance of errors in medical applications.

  • You learned to assign default parameters in the function signature using the = operator (e.g., def my_func(param=value):).

  • We established the critical syntax rule that all required parameters must be defined before any default parameters.

  • We identified and solved the major pitfall of using mutable objects (like lists) as default values, establishing the best practice of defaulting to None instead.

  • You saw how this technique is widely used in clinical software to streamline workflows, from patient data entry to complex analytical pipelines.

Mastering default parameters is a key step toward writing professional, robust Python code. Next, we will explore variable scope to understand where variables can be accessed within your programs.
