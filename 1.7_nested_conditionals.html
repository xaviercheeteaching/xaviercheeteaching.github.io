Chapter 1: Foundations of Python for Precision Health#

1. Introduction#

Welcome to the next level of decision-making in Python. So far, we have used if-elif-else to choose one path from several options. Now, we will explore nested conditionals, which allow us to model multi-step decisions where a follow-up action depends on a primary assessment. This structure is fundamental in medicine, mirroring clinical protocols where one test result or observation leads to a subsequent, more specific evaluation. In this section, you will learn how to build these decision hierarchies in code, practice with clinical scenarios, and see their application in real-world health tech systems.

2. Key Concepts and Definitions#

  • Nested Conditional: An if, if-else, or if-elif-else statement that is placed inside another conditional block. The inner condition is only evaluated if the outer condition is true, creating a dependent decision path.

  • Decision Hierarchy: A structured sequence of choices where later decisions depend on the outcomes of earlier ones. This is analogous to a clinical triage flowchart, where a patient’s path is determined by a series of sequential checks.

  • Code Block: A group of Python statements indented at the same level. In nested conditionals, the inner block has a deeper level of indentation than the outer block, visually representing the decision hierarchy.

  • Glasgow Coma Scale (GCS): A neurological scale used by clinicians to assess a person’s level of consciousness after a brain injury. A lower score indicates a more severe impairment, while a score of 15 represents a fully conscious state.

  • Tachycardia: A medical term for a heart rate that is faster than the normal resting rate. In adults, this is often defined as over 100 beats per minute and can be a sign of stress, illness, or other conditions.

3. Main Content#

3.1 The Structure of Nested Conditionals#

Nested conditionals are essential for creating logic that follows a sequence of dependent checks. The inner if statement is only executed if the outer if condition evaluates to True. This is controlled by indentation; the nested block is indented further to the right.

Consider a common clinical scenario: checking for fever and then, only if a fever is present, checking for a high heart rate (tachycardia), which could be a sign of sepsis.

# Clinical thresholds (constants)
FEVER_THRESHOLD_C = 38.0
TACHYCARDIA_THRESHOLD_BPM = 100

# Patient vitals record stored in a dictionary
patient_vitals = {
    "temperature_c": 38.5,
    "heart_rate_bpm": 110
}

# Outer condition: check for fever
if patient_vitals["temperature_c"] > FEVER_THRESHOLD_C:
    print(f"ALERT: Fever detected (Temp > {FEVER_THRESHOLD_C}°C).")
    
    # Inner (nested) condition: check for tachycardia
    # This check only runs if the first condition (fever) is True.
    if patient_vitals["heart_rate_bpm"] > TACHYCARDIA_THRESHOLD_BPM:
        print(f"ALERT: Tachycardia detected (HR > {TACHYCARDIA_THRESHOLD_BPM} bpm). Assess for sepsis.")
    else:
        print("Heart rate is within normal limits.")
else:
    print("Patient temperature is normal.")

Important: In Python, indentation is not just for readability—it defines the structure of your code. The indented code block inside an if statement only runs when that condition is True. For nested conditionals, you will have a second level of indentation. Incorrect indentation will cause errors or lead to unexpected behavior.

Pro Tip: Nesting vs. Logical Operators If a nested check has no else branch, you can often simplify it with a logical and operator. For example, if patient_vitals["temperature_c"] > FEVER_THRESHOLD_C and patient_vitals["heart_rate_bpm"] > TACHYCARDIA_THRESHOLD_BPM: is sometimes clearer. Use nesting when you must handle intermediate steps separately, such as printing the “Fever detected” alert before checking the heart rate.

4. Practice Exercises#

Medical Background: The Glasgow Coma Scale (GCS) is a neurological scale used to assess a person’s conscious state. A score of 15 indicates a fully awake person, while lower scores (ranging down to 3) signify some level of impairment. A drop in GCS, especially in the context of a head injury, is a critical finding that requires immediate attention.

Exercise 1: Assess Neurological Status Intermediate#

Objective: Use a nested conditional to implement a two-step neurological assessment based on GCS score and presence of head injury. Time: 5 minutes Medical Context: A GCS score below 15 indicates impaired consciousness. When combined with a history of head injury, it signals a high-risk situation requiring immediate specialist consultation.

Write a nested conditional using the patient_status dictionary.

  1. First, check if the gcs_score is less than the normal score.

  2. If it is, then check if head_injury is True. If so, print “Urgent neuro consult required.”

  3. If GCS is low but there is no head injury, print “Monitor GCS closely.”

  4. If the GCS score is normal, print “Patient is fully conscious.”

Solution

# Clinical thresholds (constants)
NORMAL_GCS_SCORE = 15

# Patient assessment data
patient_status = {
    "gcs_score": 13, # Range: 3-15; 15 is fully conscious
    "head_injury": True
}

# First, check for any level of impaired consciousness.
if patient_status["gcs_score"] < NORMAL_GCS_SCORE:
    # If consciousness is impaired, we then check for a known head injury.
    # This is our nested condition.
    if patient_status["head_injury"]:
        print("Urgent neuro consult required.")
    # This 'else' corresponds to the 'if head_injury' check.
    else:
        print("Monitor GCS closely.")
# This 'else' corresponds to the initial 'if gcs_score' check.
else:
    print("Patient is fully conscious.")

# Output:
# Urgent neuro consult required.

Explanation: The outer if statement checks the GCS score first. Only if the score is below 15 does the program proceed to the inner if statement, which evaluates the head_injury key to determine the final recommendation. Key Learning: Nesting allows for a primary condition to act as a gateway to more specific, secondary checks.

Exercise 2: Pediatric Medication Dosage Alert Basic#

Objective: Write a nested conditional to flag a medication order for review based on patient age and weight. Time: 5 minutes Medical Context: Dosing for pediatric patients is highly sensitive and often based on weight. A common safety check is to first identify if a patient is a child and then verify their weight is within a safe range for a given drug.

Write a script that checks the following:

  1. First, check if patient_age is less than 18.

  2. If the patient is under 18, then check if their patient_weight_kg is less than 10. If so, print “ALERT: Patient is under 10kg. Manual dosage calculation required.”

  3. If the patient is under 18 but 10kg or more, print “Pediatric patient. Standard weight-based dosing applies.”

  4. If the patient is 18 or older, print “Adult patient. Standard dosing applies.”

Use patient_age = 6 and patient_weight_kg = 8 to test your code.

patient_age = 6
patient_weight_kg = 8

if patient_age < 18:
    print("Patient is a minor.")
    if patient_weight_kg < 10:
        print("ALERT: Patient is under 10kg. Manual dosage calculation required.")
    else:
        print("Pediatric patient. Standard weight-based dosing applies.")
else:
    print("Adult patient. Standard dosing applies.")

Explanation: The code first identifies the patient as a minor. Because that condition is true, it proceeds to the nested block, which checks the weight. Since the weight is below the 10kg threshold, it triggers the specific alert. Key Learning: Nested conditionals are ideal for implementing safety checks that apply only to a specific sub-population.

Exercise 3: Sepsis Triage Protocol Advanced#

Objective: Model a simplified three-step sepsis screening protocol using nested conditionals. Time: 7 minutes Medical Context: Sepsis is a life-threatening condition. Early identification protocols (like qSOFA) involve sequential checks. A common pathway is: (1) Suspect infection? -> (2) Two or more clinical signs present? -> (3) High lactate level?

Write a script that models this logic:

  1. Check if suspected_infection is True.

  2. If it is, then check if qsofa_score is 2 or greater.

  3. If the qsofa_score is 2 or greater, then check if lactate_level is greater than 2.0. If all three conditions are met, print “CRITICAL: Sepsis Alert! Initiate sepsis bundle.”

  4. Provide appropriate feedback at each else step.

Use suspected_infection = True, qsofa_score = 2, and lactate_level = 2.5 to test.

Solution

suspected_infection = True
qsofa_score = 2
lactate_level = 2.5

if suspected_infection:
    print("Step 1: Infection suspected.")
    if qsofa_score >= 2:
        print("Step 2: Patient meets qSOFA criteria (score >= 2).")
        if lactate_level > 2.0:
            print("CRITICAL: Sepsis Alert! Initiate sepsis bundle.")
        else:
            print("Monitor lactate levels; currently < 2.0.")
    else:
        print("Infection suspected, but qSOFA < 2. Continue monitoring.")
else:
    print("No suspected infection.")

# Output:
# Step 1: Infection suspected.
# Step 2: Patient meets qSOFA criteria (score >= 2).
# CRITICAL: Sepsis Alert! Initiate sepsis bundle.

Explanation: This code uses two levels of nesting. Each if statement represents a step in the clinical protocol. A “CRITICAL” alert is only triggered if the patient passes through all three gateways, demonstrating a clear decision hierarchy. Key Learning: Multiple levels of nesting can model complex, multi-step diagnostic or treatment protocols effectively.

5. Practical Applications#

  • Automated Clinical Decision Support Systems (CDSS): In electronic health record (EHR) systems, nested logic is used to guide clinicians. For example, if a patient’s lab results show low potassium (outer condition), the system might then check if they are prescribed a diuretic (inner condition) and flag a potential drug-induced electrolyte imbalance.

  • Pharmacogenomics Alerting: These systems use nested conditionals to personalize medicine. The first check is for a specific drug prescription (e.g., Warfarin). If the drug is present, a nested check queries the patient’s genetic data for variants like CYP2C9 or VKORC1. If a relevant variant is found, an alert is triggered to recommend a non-standard dose.

  • Intelligent Ventilator Management: In an ICU, a monitoring system can use nested logic to manage ventilated patients. The outer condition might check if a patient’s oxygen saturation drops. If it does, a nested condition could check the current ventilator settings (e.g., FiO2) to see if they are already maxed out, triggering an alarm for a physician to intervene manually.

6. Summary and Key Takeaways#

In this section, we’ve explored how to use nested conditionals to build sophisticated, multi-step decision logic in Python. This structure is a powerful tool for translating complex clinical protocols into executable code, allowing for dependent checks that mirror real-world diagnostic pathways.

  • Nested conditionals create a decision hierarchy, where an inner check is only performed if an outer condition is met.

  • Indentation is the syntax that defines the nesting level. Each nested block must be indented further than the one containing it.

  • Nesting is most effective when you need to perform actions at intermediate steps of a decision process, not just at the end.

  • For simple, combined checks without intermediate steps, a single if statement with the and operator can be a cleaner alternative.
