Chapter 1: Foundations of Python for Precision Health#

1. Introduction#

Welcome to the core of clinical logic in programming. In this section, you will learn how to use comparison operators to ask questions about medical data. These operators evaluate conditions—such as whether a patient’s vital signs are within a normal range—and return a simple True or False answer. This journey will establish the fundamental skill of creating logical expressions, which is the first step in building automated clinical decision-making tools. By the end, you will be able to use comparison operators to evaluate medical data and return a Boolean result.

Important: Comparison (==) vs. Assignment (=) A single equal sign (=) is used to assign a value to a variable (e.g., patient_age = 65). A double equal sign (==) is used to compare two values (e.g., patient_age == 65). Mixing these up is a very common bug for new programmers.

2. Key Concepts and Definitions#

Understanding the following terms is crucial for using comparison operators effectively in a medical context.

  • Comparison Operator: A symbol (like >, ==, or !=) used to compare two values. In healthcare programming, these are the tools we use to check if a patient’s lab result, vital sign, or age meets a specific clinical criterion.

  • Boolean Value: A data type that can only be one of two values: True or False. A Boolean is the digital answer to a clinical yes-or-no question, such as “Does the patient have a fever?” (True) or “Is the patient’s blood pressure in the normal range?” (False).

  • Operand: The value or variable on either side of an operator. In the expression patient_age >= 65, patient_age and 65 are the operands.

  • Expression: A combination of values, variables, and operators that Python evaluates to produce a result. The expression systolic_bp_mmhg < 90 evaluates to a single Boolean value (True or False), indicating whether a patient is hypotensive.

3. Main Content#

3.1 Core Comparison Operators#

Here are the six fundamental comparison operators and their applications using medical data.

== (Equal to) This operator checks if two values are identical.

Medical Background: Blood type ‘O-’ is considered the universal red blood cell donor because its red cells lack A, B, and RhD antigens, reducing the risk of immune reactions in recipients of other blood types.

patient_blood_type = 'O+'
is_universal_donor = (patient_blood_type == UNIVERSAL_DONOR_TYPE)

print(f"Is universal donor: {is_universal_donor}")

3.2 Key Comparison Behaviors#

Debug Note: Type-Sensitive Comparisons A common bug in data processing is comparing a number to a string representation of that number (e.g., 90 == '90'). This will always evaluate to False and can lead to incorrect logic. Always ensure data types are consistent before comparison.

systolic_bp_num = 90
systolic_bp_str = '90'
print(f"Is {systolic_bp_num} == '{systolic_bp_str}'? {systolic_bp_num == systolic_bp_str}")

4. Practice Exercises#

Exercise 1: Checking for Bradycardia#

Objective: Use comparison operators to check a patient’s heart rate against clinical thresholds. Time: 5 minutes Medical Context: You are monitoring a patient’s vitals. Their heart rate is stored in the variable heart_rate_bpm = 55. As part of an automated alert system, write Python expressions to check if the rate is:

  • Below 60 bpm (a clinical threshold for bradycardia) (AHA 2023).

  • Exactly equal to 60 bpm.

  • At or above the normal minimum of 60 bpm.

Solution

BRADYCARDIA_THRESHOLD_BPM = 60
NORMAL_HEART_RATE_MIN_BPM = 60
heart_rate_bpm = 55

# 1. Check if the rate is below 60 bpm (bradycardia)
is_bradycardic = (heart_rate_bpm < BRADYCARDIA_THRESHOLD_BPM)
print(f"Patient has bradycardia: {is_bradycardic}")

# 2. Check if the rate is exactly 60 bpm
is_exactly_60 = (heart_rate_bpm == NORMAL_HEART_RATE_MIN_BPM)
print(f"Heart rate is exactly 60 bpm: {is_exactly_60}")

# 3. Check if the rate is at or above the normal minimum of 60
is_normal_or_high = (heart_rate_bpm >= NORMAL_HEART_RATE_MIN_BPM)
print(f"Heart rate is normal or high: {is_normal_or_high}")

Explanation:

  • The first expression heart_rate_bpm < 60 evaluates to True.

  • The second expression heart_rate_bpm == 60 evaluates to False.

  • The third expression heart_rate_bpm >= 60 evaluates to False.

Key Learning: Using <, ==, and >= allows for precise checks against a clinical threshold. Using constants makes the logic self-documenting.

Exercise 2: Validating Lab Result Range#

Objective: Use comparison operators to determine if a lab value falls outside a normal range. Time: 5 minutes Medical Context: A normal serum creatinine level for an adult male is typically 0.74 to 1.35 mg/dL. Values outside this range may indicate kidney problems.

A patient’s creatinine level is creatinine_level = 1.42. Write a single expression to determine if this value is outside the normal range (i.e., less than 0.74 OR greater than 1.35). You will need to use the or logical operator.

📝 Your Solution:

Solution

CREATININE_NORMAL_MIN = 0.74
CREATININE_NORMAL_MAX = 1.35
creatinine_level = 1.42

# Check if the level is outside the normal range
is_outside_range = (creatinine_level < CREATININE_NORMAL_MIN) or (creatinine_level > CREATININE_NORMAL_MAX)

print(f"Creatinine level is outside normal range: {is_outside_range}")
# Output: Creatinine level is outside normal range: True

Explanation: The expression checks two conditions. creatinine_level < CREATININE_NORMAL_MIN is False. creatinine_level > CREATININE_NORMAL_MAX is True. Because the or operator only needs one condition to be True, the entire expression evaluates to True, correctly flagging the result.

Key Learning: Combining comparison operators with logical operators (or) is essential for checking if a value falls outside a specified range.

You have two variables: patient_id_num = 1087 and patient_id_str = '1087'. Write code to:

  1. Compare if patient_id_num is equal to patient_id_str.

  2. Compare if patient_id_num is equal to the integer 1087.

print(f"Is the integer ID equal to the string ID? {is_equal_str}")

# 2. Compare the integer to another integer

Explanation:

  • The first comparison returns False because Python does not consider an integer and a string to be equal, even if they represent the same number.

  • The second comparison returns True because both operands are integers with the same value.

Key Learning: Always be aware of data types when performing comparisons. Implicit assumptions about type can lead to silent but critical failures in clinical logic.

5. Practical Applications#

Comparison operators are actively used in real-world health technology to improve patient safety and outcomes.

  • Clinical Decision Support (CDS) Systems: Hospital electronic health record (EHR) systems use comparison operators to power real-time alerts. For example, a CDS rule might continuously check if patient_temp_c > 38.0 and heart_rate_bpm > 90. If this expression evaluates to True, it can trigger a sepsis screening alert for the clinical team.

  • Automated Patient Triage Algorithms: In busy emergency departments, software uses expressions like systolic_bp_mmhg < 90 or patient_age >= 75 to assess risk factors. The True/False results from these comparisons help categorize patients by acuity level, ensuring that the most critical cases are seen first.

  • Medication Dosing and Safety Checks: Pharmacy information systems embed comparison logic to prevent errors. When a pharmacist enters a prescription, the system checks if calculated_dose_mg <= MAXIMUM_SAFE_DOSE_MG. If this returns False, the system flags the prescription for review, preventing a potential overdose.

6. Summary and Key Takeaways#

In this section, we’ve explored how comparison operators form the foundation of logical evaluation in Python. These tools are essential for translating clinical rules and guidelines into code that can interpret patient data.

  • You learned to use the six main comparison operators: ==, !=, >, <, >=, and <=.

  • We established that every comparison expression evaluates to a Boolean value: True or False.

  • We highlighted that comparisons are type-sensitive; for example, the integer 90 is not equal to the string '90'.

  • You saw how these operators are applied in real-world scenarios, from triggering clinical alerts to ensuring medication safety.

With this foundation in creating logical expressions, you are now ready to use these True and False results to control program flow in our next section on Conditional Logic.
