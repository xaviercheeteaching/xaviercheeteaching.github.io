Chapter 7: Automating Tasks with Bash Scripting#

1. Introduction#

Welcome to the core of scripting automation: variables. In precision health, we are constantly handling data—patient IDs, gene names, sequencing read counts, and lab values. Manually entering this information is slow and prone to error. Variables act as named containers, allowing us to store, retrieve, and manipulate this data efficiently. In this section, you will learn how to use Bash variables to make your scripts dynamic, reusable, and robust. We will cover how to declare variables, handle different data types, and capture command outputs, transforming static commands into powerful, automated workflows.

2. Key Concepts and Definitions#

Understanding these core concepts is crucial for using variables effectively in your scripts. Each term represents a building block for creating dynamic and reliable automations.

  • Variable: Think of a variable as a labeled container or a sticky note on a lab sample. The label is the variable’s name (e.g., patient_id), and the content inside is its value (e.g., "PT9876543A"). This allows you to refer to data by a memorable name instead of the raw value itself.

  • String: A sequence of characters treated as text. Patient identifiers, filenames, and gene symbols are all stored as strings. In Bash, strings are often enclosed in quotes (e.g., "BRCA1").

  • Integer: A whole number (without a decimal point). Integers are essential for counting operations, such as tallying the number of genetic variants found in a sample or counting the total samples in a sequencing run.

  • Hemoglobin (Hb): A protein in red blood cells that carries oxygen from the lungs to the body’s tissues. Its concentration is a common blood test parameter used to screen for conditions like anemia.

  • Body Mass Index (BMI): A value derived from the mass and height of a person, used as a screening tool to identify potential weight-related health issues.

  • Read-Only Variable: A variable whose value is “locked” and cannot be changed after it is set. This is used to protect critical, constant information, like the file path to a human reference genome, from being accidentally overwritten during script execution.

  • Command Substitution: A powerful feature that allows you to capture the output of a command and store it in a variable. For example, you could run a command to count the lines in a file (wc -l) and store that count directly into a variable named line_count.

Sticking to lowercase helps you avoid accidentally overwriting a critical system variable, which can cause unexpected script behavior.

3.2. Isolate Variables with Braces#

Now that you know how to create variables, it’s crucial to learn how to use them safely within other strings, like when creating filenames. Use curly braces ${...} to safely embed variables within text, preventing errors.

# Correct: Creates the file PT9876543A_results.txt
echo "Saving results to ${patient_id}_results.txt"
# Incorrect: Searches for a variable named patient_id_results

Debug Note If your script produces an empty value or an error when you combine a variable with text (like "$patient_id_results"), the most likely cause is a missing pair of curly braces. Bash is trying to find a single variable named patient_id_results which doesn’t exist. Always use ${variable} when it’s not separated from other text by a space.

# Double quotes expand the variable to its value.
echo "Reference genome is $genome_file"
# Single quotes treat the variable name as literal text.
echo 'Reference genome is $genome_file'

3.4. Create Read-Only Variables#

While variables are designed to be flexible, some data is too important to change. Let’s see how to protect it. Make a variable read-only with readonly to protect critical data, like a reference file path, from being overwritten.

%%bash
# Declare a variable as read-only.
readonly GENOME_FILE="/data/hg38/chr1.fa"
# This will now cause an error and stop the script.
GENOME_FILE="/new/path/file.fa"

Important Use readonly to protect variables that must not change, such as file paths to reference genomes, configuration settings, or patient identifiers loaded at the start of a script. This prevents accidental modification and acts as a crucial safety feature. By convention, readonly variables are named in ALL_CAPS. In a real script, you would also use set -e at the top, which automatically stops the script if any command fails, including an attempt to modify a read-only variable.

3.6. Command Substitution#

So far, we’ve assigned static values or simple math results to variables. A more powerful technique is to assign the output of an entire command to a variable. Use command substitution $(...) to capture a command’s output.

%%bash
# Calculate BMI from weight (kg) and height (m).
patient_weight_kg=70.5
patient_height_m=1.75
# (Formula Source: CDC 2023)
# Use the bc (basic calculator) utility for floating-point math; bash cannot do this natively.
bmi=$(echo "scale=2; $patient_weight_kg / $patient_height_m^2" | bc)
echo "Patient BMI: $bmi"

In Practice Bash itself cannot perform decimal (floating-point) arithmetic, which is essential for many clinical calculations like BMI, drug dosages, or lab value ratios. We delegate these tasks to specialized command-line tools like bc (basic calculator) or awk. Capturing their output with $(...) is a standard and powerful pattern in shell scripting.

Exercise 1: Create a Patient Summary Script (Basic)#

Objective: Practice declaring variables, performing integer arithmetic, and using variables to create filenames and generate reports. Time: 5 minutes Medical Context: In genomics, sequencing runs produce read files (R1 and R2). A common first step is to sum the reads to get a total count for quality control and create a summary file for the patient.

  1. Create a variable patient_id with the value “PT012345”.

  2. After creating the patient_id variable, make it read-only.

  3. Create two integer variables: read_count_r1 with a value of 15000 and read_count_r2 with a value of 15050.

  4. Calculate total_reads by adding the two read count variables.

  5. Using the touch command and your patient_id variable, create an empty file named PT012345_summary.txt.

  6. Finally, use echo to print the exact line: Summary for PT012345: Total reads = 30050. Your command must use the $patient_id and $total_reads variables.

Solution

#!/bin/bash

# 1. Create and 2. make patient_id read-only
patient_id="PT012345"
readonly patient_id

# 3. Create read count variables
read_count_r1=15000
read_count_r2=15050

# 4. Calculate total reads
total_reads=$((read_count_r1 + read_count_r2))

# 5. Create the summary file
touch "${patient_id}_summary.txt"

# 6. Print the summary line
echo "Summary for ${patient_id}: Total reads = ${total_reads}"

Explanation: The script first declares and locks the patient_id. It then performs integer arithmetic to calculate total_reads. Finally, it uses variable expansion with curly braces ${...} for safety to create the file and print the final report string. Key Learning: Combining variable declaration, readonly, integer arithmetic, and variable expansion to perform a complete, albeit simple, task.

Reflection Moment The readonly command in step 2 prevents the patient_id from being changed. In a complex clinical script that processes hundreds of patients, how could this single command prevent a serious data mix-up?

Exercise 2: Calculate and Report Drug Dosage (Intermediate)#

Objective: Use variables and command substitution with bc to perform a floating-point calculation. Time: 7 minutes Medical Context: Drug dosage is often calculated based on patient weight. This exercise simulates calculating a dosage in milligrams (mg) based on a prescribed amount per kilogram (kg).

Create a script that performs the following:

  1. Define a patient_weight_kg variable with a value of 82.5.

  2. Define a dosage_mg_per_kg variable with a value of 1.5.

  3. Use bc and command substitution to calculate the total_dosage_mg. The formula is weight * dosage_per_kg.

  4. Print the result in the format: Patient Weight: 82.5 kg, Total Dosage: 123.75 mg.

📝 Your Solution:

# TODO: Write your solution here
# Hint: Check the task description above
🔍 Click to reveal solution

Solution

#!/bin/bash

# 1. Define patient weight
patient_weight_kg=82.5

# 2. Define dosage per kg
dosage_mg_per_kg=1.5

# 3. Calculate total dosage using bc for floating-point math
total_dosage_mg=$(echo "scale=2; $patient_weight_kg * $dosage_mg_per_kg" | bc)

# 4. Print the formatted result
echo "Patient Weight: ${patient_weight_kg} kg, Total Dosage: ${total_dosage_mg} mg"

Explanation: Since Bash cannot handle decimal arithmetic, we pipe an expression to the bc utility. The echo command constructs the calculation as a string, and $(...) captures the output of bc into the total_dosage_mg variable. Key Learning: Using command substitution with an external tool (bc) is the standard way to perform floating-point math in Bash scripts.

Exercise 3: Generate a Timestamped Log File (Intermediate)#

Objective: Combine command substitution and variable isolation to create dynamically named files. Time: 5 minutes Medical Context: When running analysis pipelines, it’s critical to log outputs to files with unique names, often including a timestamp, to prevent overwriting results and to track when an analysis was performed.

Create a script that does the following:

  1. Create a variable analysis_type with the value "variant_calling".

  2. Use the date command with an appropriate format string and command substitution to capture the current date and time in YYYY-MM-DD_HH-MM-SS format into a variable named timestamp. (Hint: man date can show you format codes like %Y, %m, %d).

  3. Create a variable log_filename that combines the analysis_type and timestamp to form a filename like variant_calling_2025-11-11_07-21-42.log.

  4. Use echo to print the message Log file created: [your_log_filename] to the terminal.

📝 Your Solution:

# TODO: Write your solution here
# Hint: Check the task description above
🔍 Click to reveal solution

Solution

#!/bin/bash

# 1. Define the analysis type
analysis_type="variant_calling"

# 2. Capture the formatted timestamp
timestamp=$(date +"%Y-%m-%d_%H-%M-%S")

# 3. Construct the log filename
log_filename="${analysis_type}_${timestamp}.log"

# 4. Announce the log file name
echo "Log file created: ${log_filename}"

Explanation: The date +"..." command generates a formatted string. Command substitution $(...) captures this string into the timestamp variable. String concatenation is then used to build the final, unique filename. Key Learning: Command substitution is not just for calculations; it’s frequently used to capture system information like the current date to make scripts more robust.

5. Practical Applications#

Variables are indispensable in computational biology and precision health. They serve as the glue that connects different tools and automates complex workflows.

  • Dynamic File Naming in NGS Pipelines: In a genomics workflow, a script can take a patient ID as a variable. All subsequent output files—from alignment (.bam) to variant calls (.vcf)—can be automatically named using this variable (e.g., ${patient_id}.bam). This makes the pipeline scalable and eliminates manual naming errors when processing hundreds of samples.

  • Centralized Configuration Management: Scripts for complex analyses often have many parameters, such as file paths to reference genomes, annotation databases, or software executables. Storing these as readonly variables at the top of a script (e.g., readonly REF_GENOME="/data/genomes/hg38.fa") makes the script easier to read, maintain, and configure for different computing environments.

  • Automated Quality Control Reporting: A script can run a tool like FastQC, then use command substitution to grep for key metrics like “Per base sequence quality” from the output log. These metrics can be stored in variables and compared against thresholds or printed into a concise, custom summary report for a lab manager.

6. Summary and Key Takeaways#

In this section, we’ve explored how variables form the backbone of dynamic Bash scripting. By storing data in named containers, we can write flexible and powerful scripts for automating precision health tasks. We learned that proper quoting and variable isolation are critical for preventing common errors.

  • Declaration and Access: Variables are assigned with name="value" and accessed with $name or ${name}.

  • Quoting Matters: Double quotes (") allow variable expansion, while single quotes (') prevent it, treating all text literally.

  • Constants: Use readonly to protect important variables from being accidentally changed.

  • Arithmetic: Use $((...)) for integer math and $(echo "..." | bc) for floating-point math.

  • Capturing Output: Use command substitution $(command) to store the result of any command in a variable. This is a key technique for making scripts interact with other tools.

Mastering variables is the first major step toward moving from simple commands to true automation. In the next section, we will learn how to make our scripts “smart” by using conditional logic to perform different actions based on the data stored in our variables.
