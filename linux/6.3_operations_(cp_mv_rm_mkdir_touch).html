Chapter 6: Navigating the Command-Line Interface#

1. Introduction#

Welcome to the core of filesystem management. In precision health, data is everything, and how you organize it is critical for reproducibility, efficiency, and preventing errors. A single misplaced file or an incorrectly named directory can derail an entire genomic analysis pipeline. This section provides the foundational command-line tools you need to manage your digital workspace effectively. You will learn how to create, copy, move, and delete files and directories—essential skills for organizing patient data, setting up analysis projects, and maintaining a clean and logical research environment.

2. Key Concepts and Definitions#

  • Directory: A folder used to organize files. In a clinical setting, a directory for a patient (e.g., PT007890) is like that patient’s individual medical chart, holding all their related documents.

  • File: A container for storing information, such as text, data, or a program. A file like 20251111_CBC_results.txt holds specific data for a patient.

  • Path: The unique location of a file or directory in a file system. A path like /data/wgs/PT007890/raw_reads/ is the precise “address” of a patient’s genetic information.

  • Flag (or Option): A modifier, like -p or -r, that changes a command’s behavior. This is like giving a specific instruction, such as telling a filing clerk to “copy the entire patient file, including all sub-folders,” not just the cover sheet.

  • WGS (Whole Genome Sequencing): A laboratory process that determines the complete DNA sequence of an organism’s genome. The resulting data files are often very large and require careful management.

  • CBC (Complete Blood Count): A common blood test used to evaluate overall health. The results are often stored in text or structured data files.

3. Main Content#

This section covers the five fundamental commands for manipulating files and directories. Each command is a basic building block for creating and managing complex bioinformatics projects.

3.3 cp: Copy a File or Directory#

The cp command creates a duplicate of a file or directory. This is essential for creating backups, testing changes on a copy without altering the original, or applying a standard analysis template to a new dataset.

%%bash
# Copy a template analysis script and rename it for a specific patient
cp -i analysis_template.R PT007890/PT007890_somatic_analysis.R
# Recursively copy an entire patient directory to an archive, showing progress
cp -rv PT007890/ patient_archive/
# Expected output:
# 'PT007890/' -> 'patient_archive/PT007890'
# 'PT007890/genomic_data' -> 'patient_archive/PT007890/genomic_data'

3.5 rm and rmdir: Remove Files and Directories#

These commands permanently delete files and directories. They must be used with extreme caution.

Important: The rm command permanently deletes files without moving them to a trash bin. This action is generally unrecoverable. The rm -r command is especially powerful as it deletes entire directories and all their contents. Always double-check your command before executing it, and use the -i flag for an extra layer of safety.

%%bash
# Safely remove a single file with a confirmation prompt
rm -i temp_notes.txt
# Safely remove an empty directory only
rmdir empty_folder/
# Recursively remove a directory and its contents (USE WITH EXTREME CAUTION)
rm -r old_project_data/

Exercise 2: Archiving and Cleanup Intermediate#

Objective: Use cp and rm to back up and then clean up completed analysis data. Time: 5 minutes Medical Context: After a bioinformatics pipeline runs, it often leaves large intermediate files. To save storage, you archive the final results and delete the rest.

You have a directory analysis_run_04 containing final_report.pdf, raw_data.bam, and temp_log.txt. Your task is to archive the final report and then delete the entire analysis directory.

  1. Create the necessary files and directory to simulate the scenario.

  2. Create a backup directory named project_archive.

  3. Copy only the final_report.pdf into project_archive.

  4. Delete the entire analysis_run_04 directory. Use the interactive flag for safety.

Solution

# 1. Set up the scenario
mkdir -p analysis_run_04
touch analysis_run_04/final_report.pdf analysis_run_04/raw_data.bam analysis_run_04/temp_log.txt

# 2. Create archive directory
mkdir project_archive

# 3. Copy the final report to the archive
cp analysis_run_04/final_report.pdf project_archive/

# 4. Remove the original analysis directory with caution
rm -ri analysis_run_04
# You will be prompted to confirm deletion for each file and the directory.

Explanation: This exercise demonstrates a common workflow: preserving key results (cp) while cleaning up the workspace (rm -r). Using the -i flag with -r provides a file-by-file confirmation, adding a layer of safety to a dangerous command.

Key Learning: Combining cp for preservation and rm -r for cleanup is a powerful but high-stakes pattern. Always back up before you delete.

Exercise 3: Renaming for Standardization Advanced#

Objective: Use mv in a loop to rename files to conform to a standard naming convention. Time: 5 minutes Medical Context: Labs often have strict naming conventions (e.g., PatientID_SampleType_Date.extension). Raw data from a sequencer might have generic names that need to be corrected.

A sequencer has output three files: run1.fastq, run2.fastq, and run3.fastq. You need to rename them to match the patient ID PT0117 and sample type TUMOR. The final names should be PT0117_TUMOR_run1.fastq, etc.

  1. Create the three empty files.

  2. Write a for loop that renames each file according to the convention.

📝 Your Solution:

# TODO: Write your solution here
# Hint: Check the task description above
🔍 Click to reveal solution

Solution

# 1. Set up the scenario
touch run1.fastq run2.fastq run3.fastq

# 2. Use a for loop with mv to rename the files
for file in run*.fastq
do
  # The mv command renames the file in place
  mv -v "$file" "PT0117_TUMOR_$file"
done

# Verify the result with ls
ls

Explanation: This solution introduces a simple for loop. The loop iterates through each file matching the pattern run*.fastq. Inside the loop, mv renames the original filename ($file) to a new, standardized name by adding a prefix. The -v (verbose) flag confirms each renaming operation.

Key Learning: The mv command is not just for moving files; it is the primary tool for renaming. Combining it with loops allows for powerful, automated batch-renaming operations.

5. Practical Applications#

  • Setting Up a New Patient Project: A clinical bioinformatician receives a new tumor sample for sequencing. They use mkdir -p PT0123/{raw_data,analysis,reports} to instantly create a standardized, organized directory structure. This ensures all subsequent data and results are stored in a predictable and reproducible manner.

  • Applying a Standard Analysis Pipeline: A research lab has a validated R script (somatic_variant_calling.R). When a new dataset arrives, they use cp templates/somatic_variant_calling.R PT0456/analysis/ to copy the script into the new project. This prevents accidental modification of the original template and ensures consistency across analyses.

  • Data Curation and Renaming: Data from a sequencing core arrives with generic names like LANE1_S1_R1.fastq.gz. A technician uses a script with the mv command to rename it to PT0789_TUMOR_20251111_R1.fastq.gz, embedding critical metadata directly into the filename for better tracking.

  • Managing Storage by Cleaning Up Intermediate Files: A whole-genome alignment process can generate terabytes of temporary files. After the final, validated results are created, the bioinformatician uses rm to delete the large intermediate files, freeing up critical space on the high-performance computing cluster.

6. Summary and Key Takeaways#

In this section, we’ve explored the essential commands for managing the lifecycle of files and directories. Mastering mkdir, touch, cp, mv, and rm is non-negotiable for anyone working with data on the command line. These tools empower you to build logical project structures, back up critical data, standardize naming conventions, and manage storage resources effectively—all fundamental tasks in a precision health data environment.

  • Creation: Use mkdir to build your directory structure and touch to create empty placeholder files.

  • Duplication: Use cp to copy files and directories, ensuring you use the -r flag for directories.

  • Organization: Use mv to either rename files in place or move them to different directories.

  • Deletion: Use rm and rmdir with extreme caution to remove files and directories. Always favor the -i (interactive) flag with rm.

  • Caution is Key: The command line does not have a recycle bin. Actions, especially rm, are permanent. Always think twice and check your command before pressing Enter.

With these file operations mastered, you are now equipped to manage your digital workspace. The next section will focus on how to view and inspect the contents of the files you have just learned to organize.
